# 成书预处理规范

## 适用判定

默认进入本流程的是正文经数字化流程核验、达到 `human_verified` 的书籍。

Owner 明确授权在底本尚未完成全文数字化核验时翻译指定范围的，可以完成该任务必需的成书预处理。保留真实数字化状态，按对应翻译流程记录未核验风险和授权范围。先行翻译不代替底本验收；Finalization 须有 Owner 对该阶段的明确授权，不据此推导最终质量验收或发布许可。

DJVU 文字层流程内已按本规范完成目录、单元、语义分块和 block-id 的，不重复执行这些步骤。该流程允许在数字化验收前建立上述结构；结构完成不表示正文已达到 `human_verified`。

旧项目的状态名称不因与当前模板不同而批量改写。核验程度按实际工作判断，不仅凭状态名称推定；状态变更须有相应核验和验收依据。

单篇文章不进入本流程，直接依 [`ARTICLE_TRANSLATION_WORKFLOW.md`](../translation/ARTICLE_TRANSLATION_WORKFLOW.md) 翻译。

## 输入与产出

输入是所用底本的完整连续 Markdown、必要图片和作品元数据。正文状态与进入权限依上述适用判定。

书籍目录、章节单元、语义块和 block-id 在本阶段建立。数字化核验在数字化流程中完成，翻译分组、
批次、`index.json` 与 `status.json` 在翻译预处理阶段建立。

完成本阶段后，依 [`TRANSLATION_PREPROCESSING.md`](TRANSLATION_PREPROCESSING.md) 建立书籍翻译任务结构。

产出：

```text
<原文作品目录>/
  work.json
  index.md
  assets/
  <NN-slug>/
    <uNNN-slug>.md
```

## 基本单位

**单元（unit）**：按作品目录划分的内容单元。目录中的一个实际内容节点对应一个单元文件。

**块（block）**：语义／翻译单元，不是 PDF 行、OCR 行或排版行。底本与译文逐块对应，并使用相同的 block-id。

---

## 第 1 步 — 建立 work.json

在作品根目录建立 `work.json`。

至少记录：

- `work_id`
- `title`
- `year`
- `source_edition`
- `source_url`
- `digitization_route`
- `text_status`
- 扫描 PDF、数字 PDF 或 DJVU 底本的文件名与摘要（`source_scan.filename` / `source_scan.sha256`）

ISBN、`source_record_id` 等按实际底本及已有登记适用；没有时不虚构。来源没有 URL 时不虚构地址。

以上作品级信息与状态只保存在 `work.json`，不得复制到其他文件重复维护。

数字化流程另按 [`DJVU_TEXT_LAYER_WORKFLOW.md`](DJVU_TEXT_LAYER_WORKFLOW.md)、[`SCAN_DIGITIZATION_WORKFLOW.md`](SCAN_DIGITIZATION_WORKFLOW.md) 的模板写 `digitization_route` 与 `source_scan`。

完成后进入第 2 步。

---

## 第 2 步 — 拆分章节与单元

按作品目录拆分正文。

1. 目录的每个顶层节点建立一个目录，无论该节点是否为「部」。
2. 前言、后记、附录、索引等目录节点同样按目录结构处理。
3. 目录命名为：

```text
NN-slug
```

其中 `NN` 按目录顺序从 `00` 或 `01` 起编。

4. 单元文件命名为：

```text
uNNN-slug.md
```

5. `uNNN` 在全书范围内连续编号：
   - 不按目录重新起编；
   - 已分配的单元编号保持稳定；
   - 后续目录调整不得仅为恢复连续顺序而重排既有 `uNNN`。

6. 书中原有的目录页本身仍作为单元保留，不因另行生成 `index.md` 而删除。

章节文件不写 front matter。作品级信息统一保存在 `work.json`。

完成后进入第 3 步。

---

## 第 3 步 — 生成 index.md

根据作品原目录生成 `index.md`。

1. 首行为书名。
2. 其余内容为指向全部单元文件的链接。
3. 链接顺序与作品目录一致。
4. 链接层级保持原目录层级。
5. 链接文本使用目录所载标题，不自行改写、缩写或补写。

完成后进入第 4 步。

---

## 第 4 步 — 语义分块并赋予 block-id

先完成语义分块，再固化 block-id。

block-id 格式：

```text
<!-- block-id: b000001 -->
```

每个单元独立从 `b000001` 起编。

block-id 首先在底本侧赋予；生成译文时，译文侧照录对应 block-id。

### 分块原则

block 必须是可以作为独立翻译对象处理的语义单元。

赋予 block-id 前，必须先消除由 PDF、OCR、换行、分页或版面布局造成的伪边界。

不能独立理解的内容不得仅因版面边界拆成多个 block，包括：

- 被换行拆开的同一句话；
- 被分页拆开的同一句话；
- 与前后文构成一个完整句法结构的短语；
- 单独不能成立的定语或修饰结构；
- 被版面布局拆开的书名、篇名、书目题名或其他完整名称。

例如：

```text
Примеров. «Наблюдение предмета и сопоставление

его признаков»
```

这是同一条被排版换行拆开的书目题名，应合并为一个 block。

### 独立成块

下列内容各自建立 block，不并入相邻正文：

- 列表项；
- 独立成行的日期；
- 独立成行的地点；
- 独立成行的署名；
- 标题；
- 标题后的正文。

### 脚注定义块

若一个原本应合并的正文 block 中间夹有脚注定义块：

1. 合并被拆开的正文；
2. 将脚注定义块移动到合并后的正文 block 之后；
3. 脚注定义块继续保持独立；
4. 保留脚注定义块自身的 block-id。

### 已固化 block-id 的合并

若已赋予 block-id 后才发现伪边界：

1. 合并属于同一语义单元的相邻 block；
2. 合并后的 block 保留链首 block-id；
3. 被吸收 block 的 id 停止使用；
4. 不重新编号后续 block；
5. block-id 序列允许出现空档。

完成后停止本阶段。

---

## 完成条件

以下条件必须全部满足：

- `work.json` 已建立，字段与实际底本一致；
- 章节与单元已按作品目录拆分；
- 目录结构与单元文件关系完整；
- `uNNN` 已按全书顺序分配，且既有编号保持稳定；
- `index.md` 覆盖全部单元，目录顺序与层级正确，全部链接可解析；
- 全部单元已完成语义分块并赋予 block-id；
- 不存在由 PDF、OCR、换行、分页或版面布局造成的已知伪 block 边界。
