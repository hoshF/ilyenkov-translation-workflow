# 扫描 PDF 数字化流程规范

## 适用判定

以下底本使用本流程：

- 无可靠文字层的图像型 PDF；
- 扫描后附加 OCR 文字层的 PDF；
- 文字层存在乱码、漏字、错序或错误字符映射的 PDF；
- 需要以页面图像为直接证据重建正文的 PDF。

文字对象、字符映射和阅读顺序均可靠的 PDF 使用
[`DIGITAL_PDF_RECONSTRUCTION_WORKFLOW.md`](DIGITAL_PDF_RECONSTRUCTION_WORKFLOW.md)。

## 输入与产出

输入是扫描底本的页面图像。产出是从扫描页恢复的底本文字、阅读顺序和自然结构，形成经核验的
Markdown 正文、正文所需图片和作品元数据。

章节单元、语义块、block-id、翻译分组、批次、`index.json` 与 `status.json` 在后续预处理阶段建立，
翻译在翻译流程中执行。

正文达到 `human_verified` 后按作品类型分流：

- 书籍进入 [`BOOK_PREPROCESSING.md`](BOOK_PREPROCESSING.md)；
- 单篇文章直接进入 [`ARTICLE_TRANSLATION_WORKFLOW.md`](../translation/ARTICLE_TRANSLATION_WORKFLOW.md)。

Owner 明确授权在底本尚未完成全文数字化核验时翻译指定范围的，按对应翻译流程执行，并保留真实数字化状态、记录未核验风险。先行翻译不代替底本验收；Finalization 须有 Owner 对该阶段的明确授权，不据此推导最终质量验收或发布许可。

## 正文范围

数字化正文只保留文章内容。页码、页边界、分栏与分页痕迹、刊物刊头与栏眉、联系方式等属于底本载体
而不属于文章，一律不进入数字化正文；这类信息按需留在底本登记或临时目录。

## 状态

正文状态依次为：

```text
ocr_draft_unverified
        ↓
ocr_draft_human_collated
        ↓
human_verified
```

| `text_status`              | 条件                                       |
| -------------------------- | ------------------------------------------ |
| `ocr_draft_unverified`     | 已形成完整正文，尚未逐页人工核验           |
| `ocr_draft_human_collated` | 已逐页核验，仍有疑难或尚未完成最终验收     |
| `human_verified`           | 正文、注释、页面范围和关键著录信息均已确认 |

## 目录与工件

由任务明确本地底本位置、原文作品目录和临时目录。底本：

```text
<本地底本目录>/<底本文件名>.pdf
```

数字化项目：

```text
<原文作品目录>/
  work.json
  <work-id>.md
  <图片文件>
  source-issues.json  # 存在未决疑难时
```

临时处理：

```text
<临时目录>/
```

临时目录可包含页面图像、逐页 Markdown、页面元数据、OCR 原始输出、比较结果和中间文本。逐页目录不得作为最终数字化项目提交。

## 第 1 步——确认底本

1. 检查底本格式、页数、页面顺序和文字层。
2. 计算 SHA-256。
3. 检查已有底本登记及本地底本，避免重复处理相同摘要的文件。
4. 确认作品归属、`work-id`、标题、年份和版本信息。
5. 发现缺页、重页、倒页或裁切时，记录物理页序并等待明确裁决。

底本不得修改或覆盖。

## 第 2 步——登记底本

按 [`STRUCTURE.md`](../STRUCTURE.md) 在 `work.json` 中登记作品身份、版本、来源及 `source_scan.filename` / `source_scan.sha256`；字段模板见第 6 步。任务须明确实际底本位置，`work.json` 不写本机绝对路径。

已有底本登记表时更新原表中的文件位置、`work_id` / `work_ids`、格式、页数、字节数、摘要等文件属性；没有时不另建平行清单。页数及处理页面范围保留在临时核验记录。

已有来源索引时沿用其来源地址登记；没有时，在作品元数据中按实际填写仍有用的 `source_url`。不在底本清单重复维护作品书目信息、OCR 状态或数字化输出路径。

## 第 3 步——准备数字化包

按物理页序处理扫描页：

1. 渲染页面图像。
2. OCR 或人工转录页面正文。
3. 页面与物理页序的对应关系保留在临时目录，不写入数字化正文。
4. 保存逐页候选文本、图片和必要的页面元数据。
5. 合并形成完整 Markdown 候选正文。

既有 OCR、转录稿或网络文本只可作为候选或比较材料。正文状态必须按实际核验程度登记。

候选文本之间的差异只作核对线索，不直接判为 OCR 或底本错误。按页面图像核对后再决定是否修正；无法确认的内容写入 `source-issues.json`，不猜补。

## 第 4 步——整理图片

1. 保存正文理解所需的图片，排除纯装饰和重复提取图片。
2. 图片文件名在项目内保持唯一、稳定。
3. Markdown 使用相对于正文文件的路径引用图片。
4. 图片和图注保持正确对应。
5. 档案影印件无法可靠线性转录时，保留原图和经核验的图注。
6. 检查全部图片引用均可解析。

## 第 5 步——整理正文

以合并 Markdown 为工作对象，保留：

- 标题和署名；
- 正文措辞和段落结构；
- 引文；
- 列表；
- 脚注标记和脚注定义；
- 图片与图注；
- 表格；
- 参考文献；
- 与作品内容直接相关的出版说明和资助说明。

删除：

- 页眉和页脚；
- 印刷页码、页边界标记和分页痕迹；
- 运行标题和栏目栏眉；
- 刊物刊头、卷期号、ISSN 和出版商版面文字；
- 提取工具生成的无效链接和占位符；
- 邮箱、通信地址和其他联系方式；
- 与文章内容无关的页面噪声。

恢复：

- 跨页句子；
- 经下一页确认的页末断词；
- 被图片、边栏、脚注区或分页拆开的自然段；
- 多栏页面的实际阅读顺序；
- 标题、列表、引文、脚注和图注的语义结构。

不得静默改写、翻译、现代化拼写、校正事实或补齐无法确认的文字。无法确认的内容写入
`source-issues.json`，每条至少包含 `id`、`source_quote`、`issue` 和 `handling`：

```json
{
  "issues": [
    {
      "id": "S-001",
      "source_quote": "<底本原文片段>",
      "issue": "<问题>",
      "handling": "<本次如何处理>"
    }
  ]
}
```

字段要求依 [`STRUCTURE.md`](../STRUCTURE.md)。

正文文件命名为：

```text
<work-id>.md
```

## 第 6 步——建立 work.json

`work.json` 至少包含：

```json
{
  "work_id": "<work-id>",
  "title": "<标题>",
  "year": "<年份>",
  "source_edition": "<版本>",
  "source_url": "<来源页>",
  "digitization_route": "scan_digitization",
  "text_status": "<当前状态>",
  "source_scan": {
    "filename": "<底本文件名>",
    "sha256": "<SHA-256>"
  }
}
```

已核实的 DOI、ISBN 或其他关键著录信息按需加入。不得写本机绝对路径、联系方式、私人通信、页数页序或处理工具的临时状态。

## 第 7 步——逐页核验与验收

直接对照全部正文扫描页，检查：

- 正文、脚注、图注、边注和表格是否完整；
- 人名、术语、数字、日期、引文和特殊字符是否正确；
- 跨页连接和多栏阅读顺序是否正确；
- 图片与图注是否对应；
- 页面噪声和联系方式是否已删除；
- 疑难是否可定位并有明确处理意见。

逐页核验完成但仍有疑难或尚未完成最终验收时，写入 `ocr_draft_human_collated`。未决疑难写入
`source-issues.json`。

已确定的底本缺字、缺注或排印错误无法恢复时，忠实保留原貌，在 `source-issues.json` 写明依据和处理结论，不补造内容。

最终验收检查底本身份、处理范围、疑难结论、正文结构、图片、元数据和登记。Owner 可明确接受保留已确定的底本缺陷；该结论不代替未完成的页面核验。全部通过并获 Owner 明确验收后写入 `human_verified`。

## 第 8 步——整理正式工件

1. 正式目录保留 `<work-id>.md`、`work.json`、全部被引用图片，以及存在未决疑难时的 `source-issues.json`。
2. 页面渲染、OCR 原始输出、逐页候选文本和比较结果保留在临时目录。
3. 检查正式目录中的相对图片路径。

## 第 9 步——同步元数据与既有索引

确认 `work.json` 的底本身份、摘要与真实状态。已有底本登记、来源清单或作品索引时同步更新，不另建平行登记。

最终检查：

- 所有 JSON 均可解析；
- 底本 SHA-256 与登记一致；
- 正文文件名与 `work_id` 一致；
- 图片引用全部可解析；
- 正文中没有页眉、页脚、印刷页码、页边界标记、运行标题、刊头或联系方式；
- `work.json` 的底本身份与状态符合实际；
- 已使用的底本登记、来源清单和作品索引与实际文件位置一致；
- 正式目录中没有逐页中间工件。

默认不提交 Git。只有明确要求时才提交。
