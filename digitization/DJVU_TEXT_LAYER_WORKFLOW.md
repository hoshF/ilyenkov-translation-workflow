# DJVU 文字层重建流程规范

## 适用判定

带隐藏文字层（`TXTz`）的 DJVU 底本，用本流程从文字层重建正文结构。

无文字层、或文字层乱码错序的 DJVU 按 [`SCAN_DIGITIZATION_WORKFLOW.md`](SCAN_DIGITIZATION_WORKFLOW.md) 逐页转录。

本流程的第 2—4 步即按该书目录建立单元与 block-id，`rebuild` 直接产出成书形态；[`BOOK_PREPROCESSING.md`](BOOK_PREPROCESSING.md) 的命名、编号、`index.md` 与分块规则在本流程内同样适用。上述结构可在数字化验收前建立，不因结构完成而提升正文状态。

正文达到 `human_verified` 后进入 [`TRANSLATION_PREPROCESSING.md`](TRANSLATION_PREPROCESSING.md)。Owner 明确授权未完成全文数字化核验的底本先翻译时，按指定范围执行，保留真实数字化状态，并依翻译流程记录未核验风险。Finalization 须有 Owner 对该阶段的明确授权；先行翻译及定稿不代替底本验收，不据此推导最终质量验收或发布许可。

## 工具

```bash
djvudump 底本.djvu                          # 页数、每页 chunk
djvused 底本.djvu -e 'print-outline'        # 书签
djvutxt --page=N 底本.djvu                  # 单页纯文本
djvutxt --detail=word --page=N 底本.djvu    # 单页 page→line→word 结构
ddjvu -format=pnm -page=N -size=WxH 底本.djvu 输出.pnm           # 渲染整页
ddjvu -format=pnm -page=N -segment=WxH+X+Y 底本.djvu 输出.pnm    # 裁切渲染
```

第 1—4 步和第 6 步不得查看页面图像。第 5 步仅为抽取正文所需图片、核对图片及照录原印图注，渲染和查看图版所在页；不得据此开展正文逐页核验。

第 7 步按 `source-issues.json` 逐条裁切核对正文疑难，不作全书翻页。`-segment` 的 Y 原点在页面底部，与 `--detail=word` 的坐标原点一致；核对单行时按该行 bbox 加边距裁切，不渲染整页。

上述各步由 [`scripts/djvu_text_layer.py`](../scripts/djvu_text_layer.py) 执行：

```bash
python3 scripts/djvu_text_layer.py extract 底本.djvu --out 临时目录          # 第 1 步
python3 scripts/djvu_text_layer.py rebuild 临时目录 --units units.json \
    --fixes fixes.json --tables tables.json --figures figures.json \
    --source 底本.djvu --work-json 作品目录/work.json --out 临时重建目录   # 第 3、4、6 步
python3 scripts/djvu_text_layer.py crop 底本.djvu --page N --find 行内文字 --out 图.png  # 第 7 步
```

该书特有的情形——单元划分与目录层级、页码映射、OCR 修正、表格位置、图版落位——由 `units.json`、
`fixes.json`、`tables.json`、`figures.json` 给入，放临时目录，不写进脚本。格式见脚本末尾的 SCHEMA。
各卷 `work.json` 的 `source_scan` 登记底本文件名与 SHA-256，`rebuild` 据此复核底本未变。
用 `--source` 显式指定底本、`--work-json` 显式指定登记文件；不依赖脚本的项目默认位置。
重建先在临时目录生成并检查，通过后才写入指定输出；程序通过不代替下述人工核验与最终验收。

除此之外不新造常驻脚本。一次性的检查脚本放临时目录。

## 状态

```text
ocr_draft_unverified
        ↓
ocr_draft_human_collated
        ↓
human_verified
```

| `text_status`              | 条件                                             |
| -------------------------- | ------------------------------------------------ |
| `ocr_draft_unverified`     | 已形成完整正文并通过第 6 步校验，尚未对照页面图像 |
| `ocr_draft_human_collated` | 已完成第 7 步对照，仍有疑难或尚未最终验收         |
| `human_verified`           | 正文、注释、页面范围和关键著录信息均已确认       |

## 目录与工件

任务明确底本位置、原文作品目录和临时目录。正式目录：

```text
<原文作品目录>/
  work.json
  index.md
  assets/
  <NN-slug>/uNNN-<slug>.md
  source-issues.json   # 存在未决疑难时
```

任务指定的临时目录保存：

- `units.json`、`fixes.json`、`tables.json`、`figures.json`：该书特有的划分与修正数据；
- `extract` 输出（`pages.json`、`txt/`、`word/`）；
- 第 7 步的裁图与核对记录、抽图与检查用的一次性脚本、运行日志。

临时目录不进版本控制；正文与图版由底本加上述数据重放生成。

## work.json 与 source-issues.json

`work.json` 在作品根目录，至少包含：

```json
{
  "work_id": "<work-id>",
  "title": "<标题>",
  "year": "<年份>",
  "source_edition": "<版本>",
  "source_url": "<来源页>",
  "digitization_route": "djvu_text_layer",
  "text_status": "<当前状态>",
  "source_scan": {
    "filename": "<底本文件名>",
    "sha256": "<SHA-256>"
  }
}
```

ISBN、`source_record_id` 等字段按实际底本及已有登记适用；没有时不虚构。`rebuild` 按 `source_scan` 复核底本未变。作品级信息与状态只保存在 `work.json`，不复制到别处。

`source-issues.json`：

```json
{
  "issues": [
    {
      "id": "S-001",
      "source_quote": "<底本原文片段>",
      "issue": "<问题>",
      "handling": "<本次如何处理>"
    }
  ]
}
```

目录对应单一作品时不重复记 `work_id`；字段要求依 [`STRUCTURE.md`](../STRUCTURE.md)。

状态判定：未决疑难只要已定位、已登记，不阻断 `ocr_draft_human_collated`；未定位或未登记的疑难不得进入该状态。

## 疑难登记

各步遇到文字层判不了的，**当即**写入 `source-issues.json`，每条记明印张页、原文片段、问题与本次处理，不攒到最后再补。字段要求依 [`STRUCTURE.md`](../STRUCTURE.md)。

以下各类必然要记：

- 目录页缩进丢失、层级判不出的；
- 注标数与注释条数不等的页；
- 行尾连字符是否属复合词或破折号；
- 无法从上下文判定的坏字；
- 装饰性首字母（drop cap）误识；
- 行内漏词探测命中的行；
- 引号、破折号等标点的原印形式无法从文字层判定的；
- 孤立的标点噪点；
- 表头压平一类 Markdown 表达不了的版面结构。

第 7 步按这份清单集中核对。中途不为单条问题开图。

## 校正类别

文字层的错法分以下几类，逐处按该底本判正字。

候选文本之间的差异和程序探测命中只作核对线索，不直接判为 OCR 或底本错误。不能从文字层确认的内容按「疑难登记」处理，到第 7 步对照页面图像后再裁定。

所有正文改正都经 `fixes.json`，不手改正文文件。每条 `label` 写「单元或页 + 类别 + 原误识 → 正字」，判据来自页面图像的括注依据。

| 类别 | 判据 | 去向 |
| --- | --- | --- |
| 拉丁／西里尔同形 | 俄文语境里成缩写或词形（`A. Г.`、`Moлотов`）才是误识；外文条目、罗马数字、斯蒂芬努斯页码字母、数学与逻辑符号、希腊文照录 | 改正 |
| 装饰首字母误识 | 俄文不可能的词首：`Ъ`／`Ь`／`Ы` 起首、数字起首、标点起首、拉丁字母起首 | 看页面图像定正字后改正 |
| 注标误形 | 注区行首的 `'`、`"`、`/`、`\`、`` ` ``、`^`、`|`、`•`、`·`、`~`、`мм` 一类，按注区位置与页内注标数判 | 归位为星号 |
| 注标丢失 | 页内有注标、页脚注文缺标，或反之 | 按注释条数补齐或保留，记 `source-issues.json` |
| 空白丢失与多余 | 缩写之间、词与缩写之间、页码逗号后、`//` 两侧丢空格；词中被空格拆开（`раздел ьчиками`） | 改正 |
| 数字与字母互误 | `3.`／`З.`、`30`／`ЗО`、`108`／`Ю8`、`II`／`П` 一类，看上下文能否成立 | 改正 |
| 符号误读 | `→` 被给成 `->`、`-►`、`-»•` 一类 | 改正 |
| 引号与破折号 | 外层 `«…»`、内层 `„…“`；文字层给成直引号或 `{`／`}`／`v` 的，按印面统一，同卷内一致 | 统一；跨块判不定的保留并记 `source-issues.json` |

## 需要在具体底本上判断的问题

下面这些不能靠通则定，须逐一回到该底本的页面图像判；判不了的按「疑难登记」记，不猜、不静默改写。

- 注区边界与条数（书目、索引、Хроника、作者名录等页末小节）；
- 标题判据（上下空档与字宽倍数、多行标题、装饰性首字母）；
- 独立行（日期、称呼、署名）；
- 跨页接续与「页首首行右移」；
- 行尾连字符是否属复合词或破折号；
- 插页版面与图注（整页书影、题赠页、复合版）；
- 引号、破折号的原印形式；
- 坏字与专名的正字；
- 目录层级（缩进丢失时）；
- 双栏与悬挂缩进条目。

本规范里的倍数（`1.35`、`0.93`、`1.4`、`1.10`、`1.2`、`0.3`、`1.45`）与 [`scripts/djvu_text_layer.py`](../scripts/djvu_text_layer.py) 的常量一致。判据要与底本相符：判错的具体页回到页面图像复核，据以调整常量，并重跑已有各卷的判定样本。

## 第 1 步——提取

1. `djvudump` 读出总页数、每页有无 `TXTz`、以及每页图像 chunk 的类型与字节数。有 `TXTz` 的页进入本流程。
2. 计算底本 SHA-256，与既有登记核对。
3. 逐页导出 `page→line→word` 结构与纯文本，各存一份到临时目录。
4. 解析结构文件时，`(word ...)` 与 `(line ...)` 的字段分隔用 `\s+`，不用单空格。
5. **逐页比对**：结构文件解析出的字符数与同页纯文本相等。不等即解析有误，修正后重来。
6. 按下法筛出正文图片所在的页，清单交第 5 步：
   - 无 `TXTz` 的页：只有 `INFO` 而无图像 chunk 的是空白页，首末两页是封面封底，其余是整页图片。
   - 有 `TXTz` 的页：算每页图像数据字节数与该页字符数之比，明显高出全书中位数的页列为候选；二值编码（`Sjbz`）的底本必须做这一步。
   - 候选页按该页文字层内容排除表格、大字标题一类非插图内容，排除不掉的列入清单，由 Owner 抽图时确认。

## 第 2 步——页序与单元划分

1. 单元划分以**印刷目录页**为准。DJVU 书签只作线索，不作依据。
2. 印刷目录的版面分组（空行、缩进）决定层级。目录页 OCR 丢失缩进而层级判不出的，交 Owner 裁定。
3. 印刷目录平铺无层级时，每个目录条目各成一个顶层节点。
4. 建立印张页与文档页的对应，按段写入 `units.json` 的 `page_offset`。无页码插页会使偏移在
   插页处改变，插页前后各成一段，插页自身作无页码段。
5. 页序、页码对应记入临时目录的结构文件，不写入 `work.json`。
6. 顶层节点及各节题名写入 `units.json` 的 `sections`，`rebuild` 据此生成 `index.md` 的
   部／章标题与单元链接，不另行手工维护。
7. 不属正文的整页内容（无页码照片插页、扉页一类）列入 `units.json` 的 `excluded_pages`：
   它们的页落在某单元范围内，但正文不含其文字；图片按第 5 步另行交付。

## 第 3 步——版面判定

以下判定逐页独立进行。

### 度量基准

每页先算两个量，本步所有阈值以它们为单位：

- **行距中位数**：相邻行纵坐标差的中位数。
- **中位字宽**：满行正文的（行 bbox 宽度 ÷ 字符数）中位数。满行指行右端距该页右界不超过 2 倍中位字宽。

字号用平均字宽估计，不用 bbox 高度。

判据只用相对量（行距中位数、中位字宽的倍数）。

### 页眉

最顶行满足以下全部条件时剥除：位于页面上沿；行首或行尾是该页印张页码。印张页码按
`units.json` 的 `page_offset` 分段取；落在无页码段或段表之外的页不做页眉剥除。

### 篇首信息行

篇首页面上与目录登记重复的题名、署名、部题行不进正文。判定只看篇首页面最前面连续的几行，按归一化文本与所录题名、署名、部题
比对，容忍 OCR 形近字母与缩写差异；比对不上的第一行起即正文。被抑制的字符数由 `rebuild`
从字符守恒校验的页面侧扣除。

### 页下注区

自底部向上找第一个大于 `1.35 × 行距中位数` 的纵向空档。其下的块须同时满足：

- 末行贴近页面下沿；
- 空档上方有成片的满行正文可作比较基准；
- 整块不整体内缩：块内最小的 `x0` 不超出正文左界 `3` 倍段首缩进；
- 页内有注标证据，二者居一：
  - 注区行首有星号（`*`、`**`、`***`，含 OCR 认成 `^`、`\`、`` ` ``、`'`、`|`、`•`、`·`、`~`、`"` 的误形）；
  - 或页内正文确有星号注标，且该块中位字宽小于满行正文中位字宽的 `0.93` 倍。

空档上方只有标题块时不判为注释区。
书目、索引、Хроника、作者名录、«Примечания» 一类页末小节不判为注释区。

**切条**：进注区后，行首有注标或明显内缩（超出正文左界 `1.2` 倍段首缩进）的行开新条，其余行并入当前条；
行首是误形注标（`^`、`\`、`` ` ``、`'`、`|`、`·`、`~`、`"` 一类）时，该行还须内缩超过正文左界
`0.3` 倍段首缩进才算开新条；
注释没有悬挂缩进时靠行首注标分条，注标被 OCR 吃掉的行不另行拆分。
页内正文注标数作约束：候选界多于注标数时，先并掉既未内缩、行首也无注标的界，仍多则从末界起并；
首行贴着正文左界的整块是上一页末条的续排，条数上限相应加一。

### 缩进簇

该页各行 `x0` 聚类，簇间距小于半个中位字宽的并作一簇。聚类逐页做。

- 行数最多的一簇是**左界**；
- 左界右邻的一簇是**段首缩进**，两簇只差不到半个中位字宽时该页无缩进分段，按空行分段；
- 更靠右的簇是**内缩块**。

### 段落

`x0` 落在左界簇的是续行，接入当前段；落在段首簇的另起一段。

缩进行紧接在满行之后的，是悬挂缩进的续行，不是段首。

### 独立行

整行成立的日期（可带地名，如「8 мая 1952 г.」）与称呼（如「Дорогой Валентин Фердинандович!」）
各成一个块，不并入邻段；与后续正文同行时，称呼在行内切开自成一块。正文里带年份的句子不在此列。

### 内缩块

`x0` 落在内缩块簇的连续行成块。相邻行的 `x0` 之差或 `x1` 之差在半个中位字宽以内的同属一块。

块内各行 `x0` 齐平、且除末行外右端齐平的，按散文合并成一段；否则保留换行（诗行、题署、右对齐署名）。
右端须抵同一右界，参差即非散文，不合并。

### 标题

上下都有大于 `1.4 × 行距中位数` 空档的连续行构成一个块。该块同时满足以下三条时整块是标题：

- 块内各行都短于满行；
- 块内每行的字宽都 ≥ `1.05 × 中位字宽`；
- 块内至少一行的字宽 ≥ `1.10 × 中位字宽`。

整块判定，不逐行卡字宽。

单独一行的罗马数字（`I`—`IX` 一类）是节标题，不受字宽判据约束。

### 表格

数字与短词按纵向栏位对齐、栏间距远大于词间距的区域是表格。段落与内缩块规则对它无效，须单独重建：

1. 按单元格 x 中心聚类定出各栏横向位置。表内印有栏号行的可直接用它定栏。
2. 取一个每行必有值的栏，用该栏单元格的纵坐标定行；其余单元格按纵坐标归入最近的行。
3. 换行的单元格（长表头、长行名）并回同一单元格。
4. 跨栏的行单独成行，文字置于第一栏。
5. 两层以上的表头在 Markdown 中压平为单层，压平方式写入 `source-issues.json`。
6. 续页上为接续而重复的表头、栏号行与「续表」题属分页排印装置，不入正文。

表内存在可自校验的关系（同行合计、小计与合计）时逐行核对。

### 断词接合

行尾连字符默认去掉直接接合。以下情况保留：

- 接合后的词形在全书行内出现过带连字符的写法；
- 属正字法恒带连字符的组合；
- 连字符两侧都是数字；
- 行尾恰好落在词中原有的连字符，或落在破折号上。

后一条不能从文字层判定，须按第 7 步裁切该行核对。

文字层用 `¬` 表示行末断词连接符时，与连字符同等处理。

### 跨页接续

段落在页边界不闭合。下一页首行是否缩进决定接续还是另起。

下一页首行 `x0` 落在左界簇、或属下列「页首首行右移」情形时接上一段：

**页首首行右移**——文字层漏认行首词时，该行 `x0` 记的是第二个词的起点。
判据同时成立即按左界归位：`x0` 超出段首缩进；该 `x0` 在本页只此一处；行占满满版心且不越出右界；
上一页末行也是满行。

### 双栏

「缩进簇」聚出的簇远离其余各簇、且两侧各自成片时，该页是双栏。左栏读完再读右栏。

分栏前先剥出横跨两栏的标题行。

悬挂缩进的栏（人名索引一类）按「段落」一节的续行判据处理：贴栏左界的是条目起始，缩进的是续行。

正文里的悬挂缩进条目（尾注区、编号书目一类的左界编号行）同此：行首为编号／注号加空格加首字母大写的行另起一段，
其后的缩进行并入该条，直到下一个标题行或独立行为止。

## 第 4 步——注释

1. 注释区按段落规则切条，**左界取该页正文的左界**，不取注释区自身的分位数。
2. 一条注释内挤进下一条时，按行内的星号组再切。
3. 注释区首条不缩进的，是上一页注释的续排，并回上一页最后一条；其后不带星号的条同样并回。
4. 正文注标与本页注释**按出现顺序**一一对应。星号个数只作校验，不作对位依据。
5. 注标判定以页内注释条数为准，不以能否找到星号为准。
6. 注标数与注释条数不等的页，注标原样保留在正文，注释文字也并回该页正文末尾，不生成无引用的定义；该页写入 `source-issues.json`。
7. 对位后转成 `[^uNNN-NNN]`，注释定义置于单元末尾。
8. 落在标题或署名行上的注标挂到标题或署名。

## 第 5 步——图片

1. 从底本按页渲染定框抽出图片：整页渲染后按空白与密度定框，逐页核对。抽图与检查用的一次性脚本放临时目录。
2. 抽出后逐页看图，按图片内容命名，同页多张按底本中的先后：

```text
pNNN-NN-slug.扩展名
```

`pNNN` 为印张页，`NN` 为该页内序号，`slug` 取图片内容。无页码插页的前缀改用文档页 `dNNN-NN-slug`。

3. 图片存入作品目录下的 `assets/`，正文用相对正文文件的路径引用。
4. 插入位置按图片在底本中的位置定，落位与图注记入 `figures.json`。正文在插图处连续时不得为放图打断段落，图块插在紧随其后的块边界。
5. 图块的 block-id 续在单元既有末位之后，正文块编号不变。
6. 底本印有图注的照录；无图注的 alt 留空，不代拟。图片内容只写进文件名，不写进 alt。
7. 整页书影、题赠页、复合版按原版面作一张处理时，在 `source-issues.json` 记明；抽出的图片交 Owner 验收。

## 第 6 步——校验

以下全部通过才算完成：

诊断分为阻断错误、警告和待人工核验事项。已确认的结构、路径或摘要不匹配必须返回非零状态。
要求的 SHA 核验因底本、登记或其他条件缺失而无法完成时，同样返回非零状态，明确报告「未完成核验」，
不得报告为「摘要不匹配」或通过。

字符统计差额、漏词探测及异文种字母只作待核候选，不直接判定文本错误。程序退出成功不表示
本步骤全部完成；未解决的候选仍须按清单核对，不能以程序退出状态代替人工判断。

- 每页解析字符数与该页纯文本相等；
- 单元文件去掉标题、脚注定义、block-id 注释后的字符数，与所辖各页纯文本去页眉后的字符数相等，差额能逐项说明；
- 每个 block 有唯一 block-id，单元内从 `b000001` 起编，无空块；
- 脚注引用与定义一一对应，无悬空引用、无孤立定义；
- 表格每行栏数一致；
- 图片相对路径全部可解析；
- `index.md` 链接全部可解析；
- 孤立的异文种字母候选逐处核对，保留正常外文内容，确认误识的按流程处理；
- 行内漏词探测：某行 bbox 宽度 ÷ 字符数超过该页中位字宽 `1.45` 倍且行宽接近满行的，作为候选写入 `source-issues.json` 并裁图核对；无命中仅表示未发现该类候选；
- 底本 SHA-256 与登记一致；
- 重建两次输出逐字节一致（幂等）；
- 改动共享工具后，用已有各卷的判定样本回归。

## 第 7 步——对照页面图像

按 `source-issues.json` 的清单逐条裁切核对，不作全书翻页。

每条的结局只有三种：

- 能从页面唯一确定的，改正正文，该条改记为已解决，并保留原误识形式；
- 不能唯一确定的，正文保持原样，该条留在清单中；
- 属底本自身排印错误的，正文不改，该条记为底本错误。

已确定的底本缺字或缺注无法恢复时，忠实保留原貌，写明依据和处理结论，不补造内容。

本步完成后写入 `ocr_draft_human_collated`。

## 登记与验收

1. 按 [`STRUCTURE.md`](../STRUCTURE.md) 检查 `work.json` 的作品与底本标识。已有底本登记表时同步底本位置、格式、页数、字节数、SHA-256、文字层页数等文件属性；没有时不另建平行清单。页面范围及页码映射保留在临时核验记录。
2. `work.json` 的 `text_status` 与实际核验程度一致，关键著录信息（题名、编者、年份、页数、ISBN）已在版权页核对过。
3. 最终检查：

- `work.json` 与 `source-issues.json` 均可解析、字段齐全；
- `work.json` 的 `source_scan.sha256` 与底本一致；
- 全部图片引用可解析；
- `index.md` 链接可解析；
- 正文不含页眉、页码与分页痕迹；
- 正式目录不含逐页中间工件。

Owner 可明确接受保留已确定的底本缺陷；该结论不代替未完成的核验。正文、注释、处理范围、疑难结论和关键著录信息均已确认并获 Owner 明确验收后，方可写入 `human_verified`。

## 不可恢复项

文字层不携带字体信息。斜体、小型大写、字距强调在重建后全部丢失；据页面图像补强调是另一步工作，不在本流程内。
