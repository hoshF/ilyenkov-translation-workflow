# 统稿规范

本文件只适用于**全书统稿阶段**。

全书各批次 `status` 均为 `translated` 后，才能进入本流程。

从 `main` 创建统稿分支：

```text
consolidation/<作品>
```

全部统稿工作在该分支完成。

---

## 扫描与判定规则

清点、落实后的复扫以及最终核对均遵守以下规则。

- **机械扫描只用于发现候选，不直接判定错误。**
- **原文侧与译文侧交叉核对。**原文侧用于定位术语及其词形、固定形式和实际语境；译文侧用于发现旧译、非规范译法和跨单元漂移。不得以任一单侧扫描结果直接推断完整范围。
- **词形匹配必须有词界或等价的词法边界。**禁止用简单子串匹配判断术语出现。
- **按实际 occurrence 逐处判定。**同一 `block_id` 内一处合规，不代表该块其他 occurrence 合规。
- **对机械扫描无法可靠覆盖的情况进行针对性语义补查。**包括插入修饰语、回指、多义、同形异义及其他句法变体。
- glossary 的 `forms` 只记录词形和固定形式，不为插入修饰语等临时句法组合扩充。

---

## 第 1 步 — 清点

建立本轮统稿需要处理的完整问题集。

`review-notes.json` 是**译文层问题**在统稿阶段的唯一工作清单。

1. 取 `review-notes.json` 中 `checked` 为空的已有条目。
2. 按 `glossary/` 中 `approved` 条目对全书进行一致性核对。
3. 检查各批次 `<batch_id>-reports.md` 中明确留待统稿处理的问题。
4. 对机械扫描结果进行语义甄别；确认属于译文问题且尚未登记的，补入 `review-notes.json`。
5. 将待处理条目按实际问题归类。同一术语、体例、专名、记号或其他同源问题可作为一类处理。

条目格式与登记粒度依 `REVIEW_NOTES.md`。

glossary 自身的问题直接在 `glossary/` 处理，不进入 `review-notes.json`，例如：

- `zh_preferred`、`zh_alternatives` 或 `notes` 的权威问题；
- `forms` 缺漏或错误；
- glossary 条目自身的结构问题。

若 glossary 问题已经造成具体译文错误，则该译文 occurrence 仍须登记为 review-note。

清点只针对**全书视角下的一致性、术语、体例、结构及既有遗留问题**，不重新执行逐句 Full Review。

完成后进入第 2 步。

---

## 第 2 步 — 裁决

处理所有尚无明确解决方案的问题。

1. 汇总同类条目的实际原文、译文和必要上下文。
2. `solution` 为空或现有 `solution` 不足以执行时，停下等待裁决。
3. 裁决结果写入对应条目的 `solution`。
4. 涉及权威译法时，同时更新对应 glossary 条目；条目状态依 `glossary/GLOSSARY_RULES.md`。

统稿不产生长期保存的裁决 handoff、reports 或 consolidation 工作记录。

临时证据只用于支持裁决；最终结论由：

- `review-notes.json` 的 `solution`；
- glossary 的权威字段

持久保存。

完成后进入第 3 步。

---

## 第 3 步 — 落实

按问题类落实已经确定的解决方案。

1. 同一类问题集中处理全书，不按单个条目或单元零散修改。
2. 修改前核对：
   - 对应原文；
   - `file`；
   - `block_id`；
   - `comment` 中登记的其他位置；
   - 全书中同类问题的实际范围。
3. 登记数量或位置与实际文本不一致时，以实际文本为准。
4. 问题范围超出原条目的 `block_id` 时，处理所有确认属于同类问题的 occurrence。
5. 修改完成后，按原清点标准重新扫描并逐处复核。
6. 将落实该类译文修改的 commit hash 写入相关条目的 `checked`。

若复核后确认某条无需修改：

- 保持译文不动；
- 在 `solution` 中明确写明现译成立；
- `checked` 绑定到完成该结论复核时的译文状态 commit。

不得为了追求机械扫描“归零”而修改语义正确的正常语境变体。

完成后进入第 4 步。

---

## 第 4 步 — 最终复核

对全书当前状态进行收口检查。

| 对象         | 检查内容                                                     |
| ------------ | ------------------------------------------------------------ |
| review-notes | 全部条目已有明确 `solution`，且 `checked` 非空               |
| 条目定位     | `file` 与 `block_id` 均可解析                                |
| 底本与译文   | 各单元 `block_id` 序列一一对应，无重复、缺失或逆序           |
| 脚注等结构   | 依 `TRANSLATION_STYLE.md` 的结构元素规则，底本与译文对应      |
| 批次状态     | 全部为 `translated`                                          |
| commit 绑定  | 各批次 `operator_commit`、`reviewer_commit` 完整且与既有事实一致 |
| glossary     | 本轮发现的权威、结构和明确译法漂移均已解决                   |

发现新的**译文层问题**时，回到第 1 步补登。

发现 glossary 自身问题时直接修正 glossary；若因此产生具体译文问题，再回到第 1 步登记。

机械扫描仍存在但已经语义确认成立的 contextual candidate，不构成未完成项。

---

## 第 5 步 — 收尾

1. 将 `review-notes.json` 的 `source` 填为**全书翻译完成、统稿开始前的基线 commit hash**；不得填写统稿后的最终 commit。
2. 逐条确认本文件「完成条件」全部满足。
3. 将统稿分支合回 `main`，生成 `merge` 提交；`merge` 提交只负责合并，不额外修改文件。
4. 合并完成并复核 `main` 后，删除统稿分支。
5. 停止统稿流程。

统稿完成表示本轮全书问题已按本流程处理和复核，不改变原文数字化核验状态，也不代替成书排版验收或公开许可。收尾后发现新的问题，按现有工件新增必要后续处理，不改写已闭环条目或回退批次状态。

---

## 边界

翻译与审校依 `TRANSLATION_WORKFLOW.md`。

review-note 的字段、登记范围和格式依 `REVIEW_NOTES.md`。

术语归属、权威和状态依 `glossary/GLOSSARY_RULES.md`。

统稿阶段：

- 不重新执行单元或批次 Full Review；
- 不进入批次 Draft / Review / Revision / Verification 流程；
- 不产生批次级 handoff 或 reports；
- 不主动推进已经完成的批次状态；
- 若状态或 commit 字段与已有提交事实不一致，可依据明确提交证据进行事实性回填。

---

## 完成条件

以下条件必须全部满足：

- `review-notes.json` 中不存在 `checked` 为空的条目；
- 不存在尚待裁决的统稿问题；
- `source` 已绑定全书翻译完成时的基线 commit；
- 全书底本与译文结构检查通过；
- 全部批次为 `translated`；
- 全部批次必要 commit 字段完整；
- 本轮发现的 glossary 权威或结构问题全部解决；
- approved glossary 反向核对不存在尚未处理的**明确译法漂移**；
- 第 4 步的最终复核全部通过；
- 统稿分支已合并回 `main` 并删除。
