# 术语表规则

本文件规定 `glossary/` 中词条的归属、状态、权威和 `notes` 写法。

## 一、词条归属

新增词条时，先判断词条类型，再选择对应文件。

1. **专名和体制词** → `glossary.json`

   - 人名；
   - 机构名；
   - 著作名；
   - 刊名；
   - 体制、行政或职务通名，如党委会、学术委员会、教研室、研究组等。

   写入 `glossary.json` 的词条必须填写 `type`。

2. **理论或哲学概念** → 对应作者的 `<人>.json`

   - 例如伊里因科夫的理论概念写入 `ilyenkov.json`。
   - `<人>.json` **只收理论概念**，不收人名、机构名、著作名、刊名或体制词。
   - 同一概念如果在不同作者那里具有不同用法，应分别写入各自的 `<人>.json`，不得合并为一个共用条目。

3. **通用学科术语** → `terms.json`

   - 不专属于某一作者、需要跨文本保持一致的学科术语。
   - 具备下列情形之一才立条：跨单元重复出现；存在多个合理译法；专业术语容易误译；已经发生译法漂移。
   - 只在某一作者那里具有特定理论用法的词，写入该作者的 `<人>.json`，不写入 `terms.json`。

`glossary.json` 中：

- `organization`：专有机构名；
- `institution`：建制、机构类别或职务通名。

## 二、状态与权威

新增条目和 Owner 审定使用以下状态：

- `status: "provisional"`：Reviewer 提出的候选条目，等待 Owner 审定；
- `status: "approved"`：已经 Owner 审定的权威条目。

既有 `needs_review` 条目只作为待核参考，不构成权威，也不能单独作为判定译文错误的依据。Agent 只读使用，不新增、清理或批量转换这些条目；需要审定时提出建议交 Owner。

### 新增条目

新增条目一律先写为：

```json
"status": "provisional"
```

Owner 审定通过后，改为：

```json
"status": "approved"
```

### 权威规则

1. 只有 `approved` 条目的 `zh_preferred` 是既定权威译法。
2. `provisional` 条目只是候选方案，不构成新的强制翻译依据。
3. Operator 翻译同一概念和可比语境时，遵循 `approved` 条目的 `zh_preferred`；真实语境冲突按第 5 条处理。
4. Reviewer 审校术语一致性时，以 `approved` 条目的 `zh_preferred` 为准。
5. 先判断是否为同一概念和可比语境；正常语境变体不视为与权威冲突。发生真实冲突时，Operator 可以依据原文和当前语境采用暂译，并在 handoff 中写明原文、位置、现行权威、暂译及理由；不得直接修改已有 `approved` 条目，也不得把暂译作为新的长期权威。
6. 修改已有 `approved` 条目时，在 Owner 再次批准之前，原有 `approved` 译法继续保持长期权威；具体语境中的暂译不改变该权威。

`zh_preferred` 是词条的规范中文译法，其他字段不得取代其权威地位。

## 三、`notes`

`notes` 只记录**词条本身需要长期保留、并能在不同作品中复用的信息**。

概念说明、译法依据和适用边界须具有持续参考价值。
具体底本的临时裁决、审校过程、Owner 决策记录以及内部工作引用，
应分别记入对应的文献校订记录或工作日志，不写入 `notes`。

可以记录：

- 身份或基本背景；
- 历史作用；
- 译名消歧；
- 翻译提示；
- 对其他词条的引用，如 `参见 <id>`。

没有必要信息时保持为空：

```json
"notes": ""
```

### 中文写法

- 汉字之间的逗号、分号、冒号、括号用全角：`，` `；` `：` `（ ）`。
- 数字与汉字之间不加空格：`1950年代`、`第6期`。
- 拉丁文、西里尔文与汉字之间空一格：`参见 sector`、`И. П. 巴甫洛夫`。
- 外文内部的标点与空格保持原样：`（Тезисы о предмете философии）`。

### 不记录来源定位

不得在 `notes` 中写入把词条绑定到某个具体底本、版次、作品或翻译项目的信息。

这类信息不属于术语条目本身，不写入 `glossary/`。
